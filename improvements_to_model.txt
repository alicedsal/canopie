# Spatially Aware Gradient Boosting Model for Chapel Hill Projects

## 1. Decision objective

The system should answer two related but distinct questions:

1. **Need model:** Where are environmental, transportation, safety, and infrastructure needs greatest?
2. **Impact model:** Given a proposed project at a particular location, what changes are likely relative to a no-project baseline?

The recommended architecture uses separate gradient-boosting models for each outcome rather than training directly on one opaque “community benefit” score. Predicted outcomes are subsequently combined in a transparent project-ranking function.

This supports Chapel Hill’s stated priorities:

- Stormwater management
- Transportation infrastructure
- Peak-period traffic management
- Planning and development
- Long-term sustainability
- Safety for people using roads, sidewalks, and bicycle paths
- Accessibility for people with disabilities
- Bicycle infrastructure and multimodal connectivity

The strategic-goal mapping should also cover:

- Environmental stewardship
- Economic and financial stewardship
- Affordable housing
- Connected community
- Vibrant and inclusive community
- Safe community

## 2. Recommended spatial and temporal unit

### Primary analysis unit

Create a regular grid of approximately **100-meter cells**, clipped to Chapel Hill’s municipal boundary.

A 100-meter unit is appropriate because:

- Landsat thermal measurements are originally coarser than Sentinel-2 vegetation measurements.
- USGS stream-gauge readings represent watershed conditions rather than individual parcels.
- Project impacts often extend beyond parcel boundaries.
- A common grid makes raster, parcel, watershed, zoning, transportation, and project layers easier to combine.

Retain finer-resolution Sentinel-2 measurements as aggregate statistics within each cell:

- Mean
- Median
- Minimum and maximum
- Standard deviation
- Proportion below an NDVI threshold

### Secondary units

Attach each cell to:

- Parcel or parcel group
- Watershed and sub-basin
- Zoning district
- Census block group
- Chapel Hill planning district
- Nearest road segment
- Nearest transit stop
- Nearest greenway or bicycle facility

### Time unit

Use monthly or quarterly observations.

A suggested row key is:

```text
cell_id × observation_period
```

For project-effect training, use:

```text
project_id × affected_cell_id × pre/post observation_period
```

## 4. Target variables

Train one model per measurable outcome.

### Environmental targets

```text
y_heat_change
    = post_project_lst_f - expected_no_project_lst_f

y_ndvi_change
    = post_project_ndvi - expected_no_project_ndvi

y_runoff_change
    = post_project_runoff_index - expected_no_project_runoff_index

y_flood_risk_change
    = post_project_flood_probability - expected_no_project_probability
```

Negative values are beneficial for heat, runoff, and flood-risk targets.

### Transportation and safety targets

```text
y_peak_delay_change
y_bike_ped_crash_risk_change
y_walk_access_change
y_bike_access_change
y_transit_access_change
```

### Planning and community targets

```text
y_affordable_units_change
y_jobs_access_change
y_service_access_change
y_resident_satisfaction_change
```

Resident-satisfaction outcomes will probably exist only at a district or town-wide scale. They should not be assigned directly to 100-meter cells. Use a hierarchical structure:

```text
cell predictions
    → population-weighted district aggregation
    → district satisfaction model
```

## 5. Spatial weights using PySAL

Use multiple spatial relationships because different impacts operate at different scales.

### 5.1 Local adjacency

For regular grid cells:

```python
w_queen = Queen.from_dataframe(cells, ids="cell_id")
w_queen.transform = "r"
```

This captures immediate adjacency.

### 5.2 Distance-band relationships

```python
w_250 = DistanceBand.from_dataframe(
    cells,
    threshold=250,
    binary=False,
    alpha=-1.0,
    ids="cell_id"
)
w_250.transform = "r"

w_500 = DistanceBand.from_dataframe(
    cells,
    threshold=500,
    binary=False,
    alpha=-1.0,
    ids="cell_id"
)
w_500.transform = "r"
```

These encode neighborhood-scale environmental spillovers.

### 5.3 K-nearest neighbors

```python
w_knn = KNN.from_dataframe(cells, k=8, ids="cell_id")
w_knn = w_knn.symmetrize()
w_knn.transform = "r"
```

KNN weights help prevent isolated cells, particularly around irregular municipal boundaries.

### 5.4 Watershed relationships

Create a custom weights matrix linking cells that are:

- In the same sub-basin
- Hydrologically upstream or downstream
- Connected through the drainage network

Direction should be preserved for runoff modeling where possible.

### 5.5 Transportation-network relationships

Create a separate graph based on:

- Adjoining road segments
- Walkable route distance
- Bicycle-network connectivity
- Transit travel time

Euclidean adjacency alone is not adequate for transportation-access outcomes.

## 6. Spatial encodings

### 6.1 Spatially lagged explanatory variables

For selected baseline variables, calculate neighborhood summaries:

```python
from libpysal.weights import lag_spatial

for variable in [
    "ndvi_mean",
    "lst_f_mean",
    "impervious_surface_fraction",
    "bike_ped_crash_density",
    "peak_travel_delay",
    "vulnerable_population",
]:
    cells[f"{variable}_lag_q"] = lag_spatial(w_queen, cells[variable])
    cells[f"{variable}_lag_250"] = lag_spatial(w_250, cells[variable])
    cells[f"{variable}_lag_500"] = lag_spatial(w_500, cells[variable])
```

Also calculate differences between each cell and its surroundings:

```python
cells[f"{variable}_local_difference"] = (
    cells[variable] - cells[f"{variable}_lag_250"]
)
```

These help distinguish a generally hot neighborhood from an unusually hot cell within that neighborhood.
